# Матриця контролю доступу для Incident

Рівні накопичувальні: достатній відповідає «Задовільно», добрий відповідає «Добре», відмінний відповідає «Відмінно». Allow означає право на цю дію над цим ресурсом. Для кожної відмови вказано HTTP status. Роль Administrator не має додаткових прав, бо в baseline немає окремо визначених адміністративних операцій: вона діє як звичайний власник лише для власних ресурсів.

|---|---|---|---|---|---|---|---|
| Перегляд списку `GET /api/incidents` | добрий | deny, 401 | allow лише власні інциденти | allow усі інциденти | як Reporter: лише власні | Так для Reporter і Administrator | Реалізувати й перевірити: A-05 |

## Політика відмов

- Анонімний запит до будь-якого захищеного маршруту дає 401 без редиректу на HTML-сторінку.
- Reporter, який запитує чужий інцидент, і будь-хто, хто запитує неіснуючий id, отримують однакову відповідь 404 Problem Details. Статус, Content-Type і тіло збігаються, у `detail` немає id ресурсу. Відрізняється лише `traceId`.
- 403 використовується там, де ресурс користувачеві видимий, але дія для його ролі заборонена: triage для Reporter, update і delete для Analyst.
- 409 використовується, коли роль має право на дію, але поточний стан ресурсу її не дозволяє: triage не з New, delete не з New.

Обґрунтування вибору 404: однакова відповідь не показує, що чужий ресурс існує, тому id неможливо перебрати й дізнатися, які інциденти є в системі. Дані про власника й роль сервер бере лише з автентифікованого principal, а не з тіла запиту, URL чи заголовків.

## Child-ресурси

Дані інциденту можна отримати не лише через `GET /api/incidents/{id}`, а й через коментарі: список коментарів у деталях інциденту та прямий маршрут `GET /api/incident-comments/{id}`. Для коментаря рішення ухвалюється через батьківський інцидент: умова parent додається в той самий запит. Internal comment ніколи не повертається Reporter, навіть для його власного інциденту.

## Workflow статусів

New, Triaged, InProgress, Resolved, Closed. У ЛР 4 Analyst виконує лише перехід New до Triaged; наступний статус визначає сервер, а не клієнт.
